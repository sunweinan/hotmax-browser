# 性能评估

Hotmax Browser 的设计目标是减少网页任务中重复截图、图像理解和坐标定位的开销，并让结果以精简 JSON 返回。对于适合 DOM 操作的重复任务，探索 100 倍级效率提升与 token 减少是项目目标，不是已发布的测试结论。

## 比较条件

固定设备、网络、页面版本、账户状态、模型版本和任务。分别测量基于截图与坐标的流程，以及使用 Hotmax CLI 与 JavaScript 的流程。两组都必须正确完成相同操作，并使用相同的完成判定。

记录是否复用了脚本、选择器、缓存和已打开的页面。页面首次分析与后续重复执行分别报告，不能只比较熟悉页面的脚本和陌生页面的视觉流程。

## 建议任务

1. 提取表格中指定字段并输出 JSON。
2. 在测试页面填写多字段表单，提交后验证结果。
3. 翻页读取列表并去重。
4. 在多个标签之间切换并检查加载状态。

测试数据使用可公开的本地页面，不包含真实登录凭证。

## 记录方式

每项任务预热后至少重复 20 次，同时记录失败次数与重试成本。报告耗时中位数、P95、成功率、模型输入/输出 token 和调用轮次；图片 token 使用模型提供方实际计量数据，不把图片字节数换算成 token。

- 速度倍数 = 对照组总耗时 ÷ Hotmax 总耗时。
- token 倍数 = 对照组总 token ÷ Hotmax 总 token。
- 节省比例 = 1 − Hotmax 总 token ÷ 对照组总 token。

模型规划、代码生成和结果确认都应计入端到端统计。CLI 本身不调用模型，不代表整个编程助手工作流消耗为零。若脚本在多次任务中复用，应另报告摊销方式。

## 当前结果

尚未发布可复现的性能基准。现有自动化测试验证功能正确性，不用于证明速度或 token 倍数。提交基准时请同时提供测试页面、任务脚本、环境版本、原始记录与计算方式。
